## Fixes Applied

### Fix 1: `src/utils/config-loader.ts` — `isSafeModelArray` too strict (Bucket 3 / TC1211)

**Problem:** `GET /dashboard/api/config` returns model arrays with 2 elements (`[target, base_url]` — api_key stripped). When the dashboard sends that 2-element array back in a `PUT`, `isSafeModelArray` rejected it because it only accepted 1 or 3 elements. This caused every `PUT` from the dashboard to fail with `"Invalid model entry for claude.codestrong"` when the config contains per-model entries like `codestrong = ["code-strong", "", ""]`.

`TC1211 PUT empty composite target valid` failed because `getLiveModels()` gets 2-element arrays and sends them back directly, hitting this bug.

**Fix:** Changed `isSafeModelArray` to also accept 2-element arrays (length 1, 2, or 3 are now all valid). The server-side `applyDashboardConfigUpdate` already handled 2-element arrays correctly by preserving the existing api_key.

**Files changed:**
- `src/utils/config-loader.ts` line ~1249 — added `value.length !== 2` to acceptance criteria
- Rebuilt: `npm run build` → `dist/utils/config-loader.js`

**Verification:** Proxy requires restart to pick up the dist change.

### Fix 2: `testcases/05_upstream_modes/upstream_modes.test.js` — TC906 budget_tokens too low

**Problem:** TC906 (Token Counting + Thinking) sent `budget_tokens: 1000` but the proxy's validator requires `budget_tokens >= 1024` (minimum thinking budget). The request was rejected with `400: thinking.budget_tokens must be at least 1,024`.

**Fix:** Changed `budget_tokens: 1000` → `budget_tokens: 1024` in the TC906 test body.

**Verification:** Confirmed manually — `curl` with `budget_tokens: 1024` now returns `200 {"type":"token_count","input_tokens":3}`.

### Fix 3: `run-tests-loop-wrapper.js` — suite summary counts exit codes, not test cases

**Problem:** The wrapper counted 1 pass/fail per suite based on the child process exit code. All suites exit 0 (tests pass/fail internally but the suite script exits cleanly), so the summary always showed "17 passed, 0 failed" regardless of how many individual test cases failed.

**Fix:**
1. Added `casesPassed`/`casesFailed` counters.
2. Parse `Results: X passed, Y failed` lines from each suite's stdout to get real per-case counts.
3. Suite-level pass/fail now based on whether any cases failed (not just exit code).
4. Summary and markdown report now show both suite-level and case-level counts.
5. Process exits with code 1 if any cases failed (was based on suite exit codes before).

**Files changed:** `run-tests-loop-wrapper.js`
